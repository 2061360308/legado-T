# ADR-02：JS 引擎方案

## 状态
已定案。

## 背景
社区 HttpTTS / 字典源大量依赖 JS（`loginUrl`/`jsLib`/`loginCheckJs`/`showRule`），JS 引擎能力直接决定兼容率。需在不可信脚本下安全执行并支持超时中止。

## 决策
- **默认方案**：Rust 侧嵌入嵌入式 JS 引擎（`rquickjs` 或 `boa`）。
- 注入受控桥接对象（禁止文件/网络直连），仅暴露受白名单约束的请求与工具函数。
- **超时中止**：执行设置上限（默认与净化正则一致，独立可配），超时即中止并记录。
- **备选方案**：WebView 隐藏页执行（隔离弱、可控性差），仅当嵌入式引擎无法满足某社区脚本特性时启用。

## 理由
嵌入式引擎可在 Rust 进程内精确控制执行时间与能力边界，避免社区脚本越权或阻塞主进程。

## 后果
- 需维护 JS 桥接 API 契约（对应 spec 5.4/5.8 所需子集）。
- 部分依赖 Web APIs 的脚本可能不兼容，需在 M8 记录兼容清单。
